Swift State Graph

Declare where each value comes from. Swift State Graph tracks every dependency, so derived state stays correct in SwiftUI, UIKit, and plain Swift.

@GraphStored@GraphComputed

    Start with two macros

    Mark sources with @GraphStored and derived values with @GraphComputed.

    Read the quick start 
    final class Counter {
  @GraphStored var count = 0
  @GraphComputed var isEven: Bool

  init() {
    $isEven = .init { [$count] _ in
      $count.wrappedValue % 2 == 0
    }
  }
}

    Features

    Automatic dependency tracking

    Describe the result, not the updates.

    A computed node reads other nodes, and every read becomes an edge in the graph. When a source changes, only the nodes downstream of it are marked dirty. They recompute the next time someone reads them, and cache the result until then.

    @GraphStored var firstName: String = "John"
@GraphStored var lastName: String = "Doe"
@GraphComputed var fullName: String

init() {
  $fullName = .init { [$firstName, $lastName] _ in
    "\($firstName.wrappedValue) \($lastName.wrappedValue)"
  }
}
// Change firstName, and fullName follows.

    SwiftUI

    Just read the properties.

    Views observe graph properties directly, with no @ObservedObject or @State needed. Bindings come from the projected value. Conform to GraphObject to pass a model through the Environment, and use .graphTracking to keep a subscription alive only while a view is on screen.

    struct ItemListView: View {
  let store: ItemStore

  var body: some View {
    List(store.items) { item in
      Text(item.name)
    }
    TextField("New Item", text: store.$newItemName.binding)
  }
}

    UIKit and beyond

    Track changes anywhere.

    withGraphTracking re-runs only when something it read has changed. Groups and maps can nest: when a parent re-runs, its children are cancelled and created again.

    subscription = withGraphTracking {
  withGraphTrackingMap {
    viewModel.items
  } onChange: { [weak self] items in
    self?.tableView.reloadData()
  }
}

    Persistence and sharing

    UserDefaults that joins the graph.

    @GraphUserDefault reads take part in dependency tracking, and writes persist to UserDefaults. To share state between objects, assign a projected value so both point at the same node.

    @GraphUserDefault("theme")
var theme: String = "light"

final class ViewModel {
  @GraphStored var items: [Item]

  init(service: DataService) {
    $items = service.$items // the same node
  }
}

    Install with Swift Package Manager.

    Add the package, then depend on the StateGraph product. Add StateGraphNormalization for EntityStore and relational data.

    Requires Swift 6.0, iOS 17, or macOS 14 or later.

    See all releases 
    .package(
  url: "https://github.com/VergeGroup/swift-state-graph.git",
  from: "0.33.0"
)
    .target(
  name: "YourTarget",
  dependencies: ["StateGraph"]
)

    Both products ship as dynamic libraries, because StateGraph owns process-wide tracking and one process must load a single copy. Embed the frameworks once in the app target. With Tuist, use .runtimeEmbedded in the app and the default .runtime in feature frameworks.
