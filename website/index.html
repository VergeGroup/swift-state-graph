Reactive state for Swift

State as a graph of stored and computed nodes.

Declare where values come from. Swift State Graph tracks every dependency and keeps derived values correct, in SwiftUI, UIKit, or plain Swift.

Try it: change a stored node

@GraphStored@GraphComputed

    Two kinds of node. Edges are drawn for you.

    A stored node holds a source of truth. A computed node reads other nodes, and every read becomes an edge in the graph. When a source changes, only the nodes downstream of it are marked dirty, and they recompute the next time someone reads them.

    Stored

    Mutable sources of truth

    @GraphStored holds a value and notifies dependents when it changes. The type can be inferred from the initial value.

    Computed

    Derived, lazy, cached

    @GraphComputed tracks what it reads, recalculates only after a dependency changes, and caches the result until then.

    import StateGraph

final class Counter {
  @GraphStored var count = 0
  @GraphComputed var isEven: Bool

  init() {
    $isEven = .init { [$count] _ in
      $count.wrappedValue % 2 == 0
    }
  }
}

let counter = Counter()
counter.count = 5
print(counter.isEven) // false, computed for you

    Migration

    Coming from @Observable

    Stop writing validate() calls by hand. Declare the rule once and it stays true.

    Persistence

    UserDefaults that joins the graph

    @GraphUserDefault reads take part in dependency tracking, and writes persist to UserDefaults.

    Sharing

    Share a node, not a copy

    Assign a projected value to point two objects at the same node.

    @GraphUserDefault("theme")
var theme: String = "light"

final class ViewModel {
  @GraphStored var items: [Item]

  init(service: DataService) {
    $items = service.$items // same node
  }
}

    Works where your views are.

    SwiftUI observes graph properties with no extra wrappers. UIKit and other code subscribe with withGraphTracking, and the subscription re-runs only when something it read has changed.

    SwiftUI

    Read properties, get updates

    Bindings come from the projected value. Conform to GraphObject to pass a model through the Environment, and use .graphTracking to keep a subscription alive only while a view is visible.

    struct ItemListView: View {
  let store: ItemStore

  var body: some View {
    List(store.items) { item in
      Text(item.name)
    }
    TextField("New Item", text: store.$newItemName.binding)
  }
}

    UIKit

    Tracking groups and maps

    withGraphTrackingMap calls back when the mapped value changes. Groups can nest: when a parent re-runs, its children are cancelled and created again.

    subscription = withGraphTracking {
  withGraphTrackingMap {
    viewModel.items
  } onChange: { [weak self] items in
    self?.tableView.reloadData()
  }
}

    Install with Swift Package Manager.

    Add the package, then depend on the StateGraph product. Add StateGraphNormalization for EntityStore and relational data.

    .package(
  url: "https://github.com/VergeGroup/swift-state-graph.git",
  from: "0.33.0"
)
    .target(
  name: "YourTarget",
  dependencies: ["StateGraph"]
)

    Both products ship as dynamic libraries, because StateGraph owns process-wide tracking and transaction context and one process must load a single copy. Embed the frameworks once in the app target. With Tuist, use .runtimeEmbedded in the app and the default .runtime in feature frameworks.
